# User mandate: Emit epic

Begin the Emit epic from the final accepted performance checkpoint, following established project requirements and working practices.

**Organize this epic around comprehensive dependency completion, building upward.** Identify the subsystems emit depends on, establish their dependency order, and complete coherent subsystems before building their consumers. We are no longer doing bounded vertical slices. The purpose is to reduce repeated dependency discovery, partial implementations, and integration rework across the epic.

Define completion from the pinned upstream implementation. Account for required factory and transformation infrastructure, printing, helpers, JavaScript and declaration emit, source maps, and output and option behavior. Determine the precise subsystem boundaries and implementation sequence yourself. Include required supporting dependencies without reopening completed foundations absent a concrete need.

Share a concise contract and roadmap, then execute autonomously through implementation, review, verification, and committed campaign checkpoints. Do not stop after planning or seek another assignment between campaigns.

Retain Astra coordination, GPT-6.1 Sol implementation and independent review, upstream fidelity, direct Go-to-C# source mapping, readable C#, appropriate .NET libraries, xUnit, and actual Linux x64 Native AOT verification.

Port genuine upstream algorithms and preserve semantic behavior. Do not use permissive placeholders, fixture-specific shortcuts, or silently omitted outputs. Preserve the performance epic's accepted fixes and .NET adaptations, documenting and verifying any necessary changes.

Use the complete applicable upstream test inventory and pinned-Go comparisons as the primary acceptance evidence:

- Account for in-scope implementations, partial paths, and test dispositions. Separate implementation gaps from verification limitations.
- Preserve upstream assertions and expected outputs. Compare emitted files, diagnostics, and relevant behavior under equivalent inputs and options.
- Reuse upstream fixtures for CLI, runtime, declaration, and source-map verification. Add focused tests where concrete coverage gaps remain.
- Require independent review of subsystem and final completion claims, actual Native AOT execution, and applicable retained correctness and performance regression gates.
No external open-source project is required. Defer VS Code and other external-project evaluations until emit acceptance.

Own delegation, agent reuse, build scheduling, and validation frequency. Use targeted checks during development and comprehensive gates at appropriate checkpoints. Keep progress updates concise and project state resumable. Improve execution efficiency from observed evidence without weakening acceptance.

Continue until the whole-emit contract is satisfied. Raise only material blockers, unavailable access, or scope decisions; ordinary defects and failed tests are work to resolve. Language services and unrelated build/watch orchestration remain outside scope.

Finish with committed changes, a clean working tree, reproducible compilation and acceptance commands, updated source mapping, and a completion assessment stating supported behavior and residual verification limitations. Report observed effort without inventing unavailable measurements.
