## Actual semantic boundaries

Glob traversal follows accessible symlink directories, records canonical real paths before descending, and visits a real directory once. Output keeps the original visited spelling. Files are processed before child directories and bucketed by first matching include, then buckets are flattened in include order. Accessible entries inherit Go lexical byte order from the FS; stable include-base sorting uses the path comparer. A generic alphabetical sort of final output would change semantics.

WalkDir instead merges/sorts file and directory names into lexical visitation, reports symbolic links without following them (including a symlink root), preserves SkipDir/SkipAll semantics and invokes callbacks on missing roots. Non-nil empty symlink metadata means known absence; nil means fallback Realpath probing. Directory enumeration failure is indistinguishable from an empty directory because the upstream FS method has no error return. Stat follows symlinks; a reported link's Info is synthesized from name/mode without lstat.

Matcher `?` and star backtracking consume UTF-8 runes. Literal insensitive comparison uses Go EqualFold; canonical path keys use the distinct filename-lowering policy, including dotted-I handling. Roots compare case-insensitively even when the remaining path is sensitive. Dynamic roots preserve opaque identity and force sensitive patterns. Include wildcards skip hidden/package folders and implicit `.min.js`; explicit literal paths/excludes have different rules. These are source rules, not .NET glob or OrdinalIgnoreCase equivalents.

The general VFS must support deterministic virtual POSIX/drive/UNC/dynamic fixtures regardless of the current Linux host. OS case sensitivity is a detected property, not inferred exclusively from the OS name; platform support claims require actual platform evidence. Typed paths and virtual FS preserve original Go byte strings, including non-scalar/invalid sequences; no replacement decoding or OS representability rejection occurs in pure interpretation. Only the actual .NET OS boundary rejects unrepresentable paths before system calls. The existing bounded Projects scalar path adapter remains separate. ReadFile strips UTF-8 BOM and decodes little/big-endian UTF-16 BOM using the actual upstream replacement/truncation behavior; no-BOM bytes remain unchanged.

## Resolver closure and expansion risk

Relative/rooted extends first probes the exact file and conditionally appends `.json`, retaining the original error/range and inheritance-relative path rebasing. Bare extends calls ResolveConfig, which constructs fresh NodeNext options, selects CommonJS conditions, sets Json-only extension bits and marks config lookup. This does **not** disable package imports, self-name or exports. Required package resolution includes scoped names, nearest ancestor node_modules, package `tsconfig`, default `tsconfig.json`, ordered conditional/pattern/array targets, `typesVersions` with semver/path substitution, package metadata cache and original/symlink result identities. JSON-only suppresses @types/source-extension passes; fresh options suppress user paths/baseUrl/rootDirs and output/input remapping, which must be established at original condition sites rather than replaced by nil results.

Content-mapper manifest discovery constructs Bundler options and calls ResolvePackageDirectory. The source directory-only early return selects the package directory before exports/entrypoint loading; it still needs scoped-name parsing, ancestor lookup and symlink result projection. Parsing its manifest requires name/version and typed `typescript.contentMapper` fields. It never executes a mapper. That metadata interpretation is coherent config scope; external execution and content transformation remain separate capabilities.

## API seam and ownership proposal

Use the source read-side FS operations CaseSensitivity, FileExists, ReadFile, DirectoryExists, GetAccessibleEntries, Stat and Realpath with rooted file/directory/path intent types, PathKey, FileSpec and PathPattern. ReadFile returns the actual Go byte-string plus success; failure differs from a successful empty file. Entries preserve nullable Files/Directories and nullable Symlinks metadata. Config parsing consumes this seam directly, not an adapter that filters options or discovered files to what the semantic checker currently supports.

ReadDirectory receives host, directory, extensions, excludes, includes and depth; NewSpecMatcher receives specs, directory, Usage and case sensitivity. Preserve null matcher vs allocated matcher with no successful pattern and nil/empty collections. ResolveConfig(name, containing file, FS) uses its original fixed options; ResolvePackageDirectory uses the original resolver/host options and result record, with no semantic checker dependency. Agreed names: TypeScript.Vfs.IFS; rooted/pattern/key wrappers in TypeScript.Scanner; TypeScript.Modules.DefaultResolver.ResolveConfig and ResolvePackageDirectory. Pure path strings are original Go bytes; ReadFile uses the same byte representation. Semver two-file source port is now on disk, not yet built or independently tested.
