## Completion risks and handoff

- Full generated metadata may require many currently unretained option fields and
  arbitrary raw option values. Partial field enumeration creates false completion.
- A source API can produce positioned diagnostics where JSON-value APIs cannot;
  treating them as interchangeable loses required behavior and owner identity.
- Extends order/cycles, explicit null overrides, inherited files relative to the
  base config and configDir copy-on-write/cache replay need original outcomes.
- Discovery is not a recursive file listing: extension groups, literal-file precedence,
  default excludes, node_modules/dot matching, case/dynamic roots and symlink handling
  affect exact filenames and order. Missing/unreadable is not an arbitrary empty success.
- Full interpretation includes package extends and mapper metadata without launching
  code. Resolver/semver/manifest errors must remain real rather than authored Unsupported.
- ParsedCommandLine exposes output/reference/match/reload behavior beyond tests that
  happen to run. Core's function-level implementation inventory must separately account
  for every subsystem entry/helper and explicit execution omissions.

API seams are being coordinated directly with core/support before new shared bodies
or production dependencies are written. Core remains the only shared library builder;
verification consumes immutable snapshots. No new agents are used. Root subsequently
authorized verification's diagnosticwriter counterpart and tests/oracle implementation;
