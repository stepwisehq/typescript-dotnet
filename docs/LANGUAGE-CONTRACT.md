## Verification strategy

Use genuine pinned libraries and original fixture declarations, units, configuration
variants and host assumptions. Distinguish preserved original test assertions, documented
no-emit adaptations, compiler-input reuse and authored interaction tests. Preserve whole
mixed fixtures; do not erase syntax, replace options, suppress missing globals or weaken
diagnostics. Include invalid inference/relationship/module/runtime/decorator paths and
cross-feature interactions with generics, flow, recursive types and protocols.

Original tests' full type/symbol traversal is a public assertion domain, not private-state
parity. Existing focused repeat/root/query-order controls are used where behavior depends
on lazy caches; additional instrumentation requires a concrete defect or invariant.
Failures remain failures until the source or a demonstrable harness defect is repaired.

Build coherent source packets centrally. Use the complete original no-emit runner for
responsibility-selected managed feedback batches, then the whole applicable inventory;
avoid constructing a separate finite-corpus framework when that same runner suffices.
Retain focused authored interactions and ordinary CLI controls where they cover an actual
blind spot. Perform comprehensive native/retained acceptance after source and assertion
review; one final run can satisfy both language and whole-checker gates when ready.
Do not repeat broad gates at every internal feature handoff. Keep implementation status,
executed evidence, exclusions of genuinely external operations and unresolved verification
gaps distinct. No campaign or context boundary requires renewed user authorization.
